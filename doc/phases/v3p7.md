# V3P7 计划 — pForth 移植 + V3 收尾

> 日期: 2026-06-02
> 状态: 计划阶段

## 背景

V4 规划后决定：不单列 V4，将唯一的新功能（Forth 解释器）并入 V3P7，与 V3 收尾工作并行。
RTL 不动，所有新增功能为纯 C 实现。

## V3P7 范围

### 1. Forth 解释器（主目标）

**方案**: 移植 [pForth](https://github.com/profburke/pforth) 到 NEORV32 bare-metal

选择理由：
- 纯 ANSI C，与现有 sw/lib 代码库无缝集成
- 移植只需实现 3 个 I/O 函数（`pf_getc`/`pf_putc`/`pf_init`）
- 字典可导出为 C 源文件（目标端不需要文件系统）
- 桌面端先开发调试，再交叉编译到 RISC-V
- 有测试套件（John Hayes coretest）

**集成方式**:
- 作为 shell 命令 `forth` 注册（类似 `snake`/`conway`）
- 输入源：PS/2 键盘 + UART（复用 VGA 终端）
- 输出：VGA 文本终端（复用 `vga_hal.c`）
- F1 帮助 / F10 退出，遵循现有统一操作逻辑
- FreeRTOS 独立任务 or 程序内主循环（待定）

**移植步骤**:
1. 克隆 pForth，桌面编译验证
2. 创建 `sw/lib/pforth/` 子目录，复制 csrc/
3. 实现目标平台 I/O 层（`pf_io_neorv32.c`）
   - `pf_getc()`: 从 PS/2 MMIO 或 VGA 键盘缓冲区读字符
   - `pf_putc()`: 通过 VGA HAL 写字符
   - `pf_init()`: 初始化 Forth 数据/返回栈
4. 修改 makefile：桌面编译字典 → 导出为 C 头文件
5. 集成到 de2shell_rtos：注册 `forth` 命令
6. 上板验证基本操作：`5 3 + .` → `8`、`: square dup * ;`、F1/F10
7. 运行 coretest 基本子集

**预估工作量**: pForth 核心 ~3K 行 C + I/O 层 ~100 行 + 集成

## 已确定候选（原 V4 列表，供后续参考）

以下功能需要 RTL 变更，当前阶段不做：

| 功能 | 阻塞原因 |
|------|---------|
| SD 卡文件系统 + SPI 控制器 | 需要新 RTL 外设 |
| SD 卡启动（替代 UART 上传） | 依赖 SD 卡驱动 |
| ICACHE 使能 | NEORV32 上游问题，非本项目领域 |
| 文本编辑器 | 依赖文件系统 |
| 数字时钟 / RTC | DE2-115 无带电池 RTC，CLINT 断电归零 |
| DCACHE | 优先级低于 ICACHE |
| 硬件断点 / 单步 | 需 OCD RTL 集成 |

## 排除项

- ~~以太网 (DE2-115 ↔ A7Pro 互连)~~ — 架构目标完全不同，UART 已足够
- ~~数字时钟~~ — 无电池 RTC，软件时钟无持久性
